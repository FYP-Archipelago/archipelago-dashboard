# Product UI preferences

Treat Archipelago as an interactive application. The user explicitly prefers compact controls, charts and counters over a report-like layout.

- Use direct labels and restrained styling that fit the existing dashboard. Small metric boxes are appropriate. Avoid decorative cards, oversized hero sections, gratuitous icons and generic generated-dashboard copy.
- Keep headings and supporting lines brief. Add context only when it explains behavior or a limitation specific to this program and helps the user act.
- Do not teach evolutionary algorithms or explain self-evident chart conventions in the interface. Avoid narrative summaries, repeated descriptions and paragraphs explaining zeros, axes or colours when labels can convey the meaning.
- Prefer progressive disclosure for detailed records. The Migration tab's All routes list starts closed.
- Keep scientific calculations and metric aggregation in Python. The frontend presents supplied data and handles user interaction.
- Apply these preferences to future UI ideas and changes across the project. Make changes to the requested view first, preserving the established visual style.
