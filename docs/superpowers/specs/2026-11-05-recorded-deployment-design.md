# Recorded deployment design

Deploy `feat/backend-integration` to the existing Vercel project with an explicit build-time recorded-data mode. The user has no public backend and requested saved data, not live runs. Preserve the current viewer and tabs. Python prepares final clustered Results from the two already-public recordings; the browser loads those files without scientific computation. A static demo API adapter supports result/explanation reads and a fixed recording library, never POSTs or invented execution. Recorded mode replaces the new-run form with a recording selector; real backend mode retains its current behavior. Configuration identifies recorded runner settings and offline clustering parameters. Unavailable convergence/migration timing is labelled rather than fabricated.

Only derived Result artifacts and whitelisted metadata are published; raw CSV, genomes, host diagnostics and private logs are excluded from the Vercel upload. Enable `VITE_RECORDED_DEMO=true` for the hosted project. Connect/configure production to `feat/backend-integration` if Vercel Git access permits. Verify unit tests, build, actual deployed assets/data, all tabs and graph controls before reporting deployment success. No main merge or backend PR merge.
